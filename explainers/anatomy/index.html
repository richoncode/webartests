How Anatomy works

Anatomy is an open-source agent skill that explains a technical idea by having the agent build a working, interactive isometric machine instead of a boxes-and-arrows diagram. This page walks through its pipeline, parts and actual instructions, all taken from the repository source.

The one idea: “The object is the explanation. Don't draw boxes, arrows and labels. Invent a real, well-made physical thing whose working is the concept.” — SKILL.md

A cache key becomes a pin-tumbler lock. One GPU context serving many canvases becomes a gantry plotter whose single print head visits 16 wells. Every number the figure shows comes from the same model that moves its parts.

The flow: prompt → verified figure

SKILL.md sets out a ten-step workflow and says to “write the concept and the parts list before any geometry. Most of the quality is decided there.”

plan

Size it

Pick a tier first: Figure, Hero or Epic. Quote time for a Hero; never start an Epic without the user choosing it.

plan

Truth first

Collect real sizes, counts, thresholds and curves. Ideally write a small pure model module that drives the readout, motion and caption.

plan

Invent the object

A machine whose mechanism maps one-to-one onto the concept, stated in one sentence: what moves and what that means.

plan

Parts list

At least 40 parts, grouped into base, structure, mechanism, controls and the one lit subject.

plan

Plan the world

World units of about 1 px, an azimuth of 45° and an elevation of 30° by default, fitted with fitProjection.

build

Build geometry once

Precompute static paths with the kit (slabOf, cylinder, knurl, lathe, tube…). Rebuild per frame only what changes shape.

build

Paint back to front

Painter's order. With pipes and round parts, A.settle measures true depth and A.auditOrExit ends the build.

build

Frame it

A card with Fig n, a title, a hint and a live readout. Words stay out of the drawing.

build

Make it live

Calm, eased motion and an idle tour. Responds to pointer and keyboard and goes still under reduced motion.

verify

Verify like a critic

Headless Chrome captures at desktop and 390 px, an audit and a line check run down to 0, 4× close-ups in both themes, and the agent reads every PNG.

Plan (no geometry yet)Active step

Time-keeping is built in: “have a working page that opens in the browser within the first hour”. The agent runs date at each step and reports back if a step takes more than twice its share.

references/
Truth-first modelOne pure module drives everything

In the test-rig walkthrough the behaviour was copied into a pure model, rig.ts, from the library source: rest size 120 × 32, a press that swells it by 8%, a rubber-band lean give·(1−1/(1+0.55·d/give)) and three springs. “The readout, the aria text, the caption numbers and every moving part read from this one model.”

walkthrough.md
The kit (renderer)kit/ — zero-dependency drawing core
  • iso-kit.ts/.mjs: camera, solids, parts library, SVG string renderer, card and page builders
  • lathe.mjs (round parts) and tube.mjs (pipes and cables)
  • gl.mjs: a WebGL layer between a back SVG and a front SVG, in the same isometric camera
  • turn*.mjs: the 3D mode (beta)
  • react/draw.tsx and react/live.tsx
kit/
Geometry auditkit/audit.mjs — proof, not eyeballing

recorder collects true shapes, settle ray-casts overlapping pairs for real depth, and auditOrExit runs clearance, terminal, loose-end, support, fold, crowding, stand-in, wobble and depth-order checks. It exits non-zero on any problem. The craft notes say the Raptor's hand-set keys “looked right at 1× and had 323 depth-order problems.”

kit/audit.mjs
Chrome self-checkscripts/ — the agent looks at its own work
  • capture.mjs: headless Chrome screenshots (desktop 1440, phone 390, hover, timed shots, 4× zoom, reduced motion). It also prints console errors and whether the page scrolls sideways.
  • drive.mjs: scripted sequences, slow motion, contact sheets that catch pops, --no-webgl
  • lines.mjs: every line must end on something; it must print line ends: 0
  • turn-check.mjs: 3D fidelity, order, pops and performance
scripts/
OutputsSource you own
  • A Node build.mjs that writes a standalone HTML page (add --light for the light theme)
  • A lone .svg via figureSvg({standalone})
  • React/Next.js: geometry modules, a server component and one client component
  • Optional A4 PDFs in poster, drawing or detailed format (print.mjs)
  • Optional gallery pull request (publish.mjs), only when you ask
Evalsevals/evals.json

How it maps the real thing to machine parts

The repo's answer is a fixed order: find the true behaviour, then choose a machine whose mechanism matches it one-to-one, then list parts by job, then drive every moving part and number from one model. Below is what each rule says, with its source.

1 · Truth before metaphor
SKILL.md
“Collect the real numbers and behaviour of the thing being explained: sizes, counts, thresholds, curves. The readout, motion and caption must all be true.”

The model is meant to be a small pure module that everything reads from. In the test rig, “the readout, the aria text, the caption numbers and every moving part read from this one model” (references/walkthrough.md).

2 · Choosing the machine
SKILL.md
“Pick a machine, tool, instrument or piece of furniture whose mechanism maps one-to-one onto the concept. Say in one sentence what moves and what that motion means. Never copy a reference image: take its finish, not its object.”

SKILL.md gives earlier mappings as a guide: a cache key that skips work becomes a pin-tumbler lock (“when every pin matches, the plug turns and nothing is redrawn”), seven render targets with different bytes per texel become seven drawers “each as deep as its bytes”, and a separable blur (49 × 49 taps against 49 + 49) becomes a bed-of-nails stamp beside two combs. The README adds one rule of thumb: “An idea that has no mechanism to build will come out weaker.” Not specified: the repo gives no scoring method or checklist for choosing between candidate machines. It relies on the one-sentence test and the examples.

3 · Parts list, grouped by job
SKILL.md
“Write at least 40 parts (40–80 for a Figure, 80–150 for a Hero, more for an Epic), grouped: base …, structure …, mechanism …, controls … and the subject itself, which is the one lit part. Each part sits on another part.”
  • Tone follows role: “Base and feet are lo, structure is mid and the subject is hi. Exactly one accent is lit … the part the reader should watch” (SKILL.md).
  • Every part has a job: it “rests on another part, aligns to its neighbours and has a job. Density comes from structure …, not from texture” (references/craft.md).
4 · No decorative or misleading parts
references/verify.md
“add the real parts that belong there (screws, seams, bevels, label plates, scales, the brackets that hold things), never decoration that belongs to no part.”
  • “Purposeful, never noise. Detail comes from parts that belong to the mechanism” (SKILL.md).
  • The craft anti-patterns reject abstract stacks, one plain slab, floating labels, and colour “unless colour is the subject” (references/craft.md).
  • Numbers can't drift from motion: the readout's “words and numbers come from the same instant”. The verify checklist warns against a phase word next to a lagging gauge that reads “relief 85 bar before the valve has cracked” (references/verify.md).

Worked example: the test rig (Fig 6)

This is the repo's only full worked example (references/walkthrough.md, code in examples/test-rig/). It explains how a glass UI button responds to touch. The LRU cache and other machines shown in the video aren't documented in the repo.

Motion follows the model too: one loop steps the spring model and writes every changed attribute. Under reduced motion “the springs become critically damped: the glass still swells, but it never leans or bounces.” The base, frame, screws and label plate are structure that holds the mechanism; they don't stand for parts of the real system.

How verification checks the alignment

  • The review checklist opens with: “Its mechanism maps to the concept: what moves and what that means can be said in one sentence” and “Every number is true and comes from the model. The readout changes as things move” (references/verify.md).
  • Limit: this check is a judgment against the checklist. No script compares the machine to the real system. Code checks cover geometry and lines, not whether the metaphor is right.

How it checks itself

Anatomy makes calls like this example agent remark:

“It works end to end, but the card and stage are too small for the plate, so the story gets lost in empty bench. I'm compressing the stations and enlarging the card, the punch and the stage.”

A judgment like that comes from this loop:

Know what matters

The concept and parts list come before geometry, with one lit subject “the reader should watch.” That's what “the story gets lost” is measured against (SKILL.md).

Capture in headless Chrome

“Capture desktop, phone (390 wide), hover and several moments of motion with scripts/capture.mjs”, plus “4× close-ups of every junction in both themes” (SKILL.md).

Look at every image

“Read every PNG you make: open it and look” (references/verify.md). The agent is a model that can read images, so it sees where the space goes.

Judge against intent

The composition rule: “Centre the figure and let it fill about 55–65% of the card … make sure it still reads at 390 px wide.” For phones: “If parts get too small, scale the SVG up to about 110–118%” (references/craft.md). “A bare face or an empty corner is unfinished work, not calm” (SKILL.md). Then: “Iterate until yes.”

Code proves geometry, not composition

kit/audit.mjs must end “audit passed”, and scripts/lines.mjs must print “line ends: 0”. Its own rules warn against fixing by eye: the Raptor “looked right at 1× and had 323 depth-order problems” (references/craft.md). Neither script judges layout or story.

Honest limit: the composition call is the model's own eye checked against written rules such as 55–65% fill, not a measurement. It can be wrong, so a person should still look. The repo's own site reportedly says Claude is good at building these figures but not always at seeing them; I haven't checked that quote against the site.

The actual instructions

Short excerpts quoted verbatim from the repository (main branch, commit 1482e84). Copy buttons copy the quoted text.

Try it

Install, then ask (README)
npx skills add wheresryan22/anatomy -g /anatomy explain how a token bucket rate limiter works, interactive

The README's three habits: name the idea with its real numbers, or name the object and say what should move, and say where it will live (HTML, SVG or React; light or dark). In Codex, type $anatomy.

Limits (README)

  • “It is not a chart library.” No axes or plots.
  • It draws machines, instruments, tools and furniture, not people or exact maps.
  • “It is slow on purpose.”
  • Shaders need WebGL, but the SVG still reads without it.
  • 3D mode is beta: about 20 fps for the 380-part stress hand at 1440 px, and 13–15 fps on a throttled phone profile.
