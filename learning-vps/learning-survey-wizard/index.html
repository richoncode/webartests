Module 1

Background & The Core Spatial Problem

Learn why standard, consumer-focused photo and video pipelines completely corrupt high-precision 3D reconstruction and Visual Positioning datasets.

Structure-from-Motion (SfM) vs. Video Capture

Traditional video capture is designed for human eyes, operating on the principle of local aesthetic appeal. It dynamically adjusts focal distance, exposure duration, and sensor sensitivity (ISO) as frames progress. However, photogrammetry algorithms—such as COLMAP's Structure-from-Motion (SfM) pipeline—rely on extracting consistent mathematical invariants.

When matching keypoints (using algorithms like SIFT) across adjacent image sequences, the pipeline assumes a static world and photometric consistency. If pixel values change because the camera auto-adjusts its parameters, feature matches degrade, rendering reconstruction metrics highly inaccurate.

The iOS Platform Constraints

To deploy spatial mapping apps onto mobile hardware like iPhones, engineers must navigate extreme resource constraints. Under high disk I/O demands, saving raw, uncompressed files will quickly saturate write speeds, cause frame drops, and deplete local memory. We must lock AVFoundation hardware controls completely.

Module 2

The Rig Geometry Dilemma — Fixed Rig vs. Independent

Quantify the mathematical speedups and accuracy gains made possible by constraining camera layouts in physically rigid mounts.

Degrees of Freedom in Bundle Adjustment

When processing multiple image paths to construct a sparse point cloud, optimization solvers must calculate the 3D position of each feature point alongside the 6-DoF pose (3 rotation, 3 translation variables) of each camera viewpoint.

In Independent Mode, every camera viewpoint moves independently. For a collection of $F$ frames and $N$ cameras, the solver must optimize $6 \times F \times N$ camera variables.

In Fixed Rig Mode, cameras are locked together on a rigid bracket. The relative transform between cameras (extrinsics) is constant. This reduces variables to $(6 \times F) + 6 \times (N - 1)$.

Solver Optimizations & Trajectory Precision

Reducing variables directly reduces the size of the Jacobian matrix within Ceres bundle adjustment solvers, yielding a 50% to 70% decrease in global solve times.

Additionally, locking the spatial baseline prevents scale drift, increasing structural mapping precision by up to 29.38% against ground-truth LiDAR reference systems.

Module 3

Infrastructure-Free P2P Networking & Control Sync

Coordinate settings and commands across multiple mapping devices in remote locations, tunnels, or fields with zero cellular or router connectivity.

Master-Satellite Topology

To achieve synchronized recording, the hardware fleet behaves as a unified capture array. One node is designated as the Master device, hosting the interactive controls. The other nodes act as Satellite devices, running a headless process that accepts JSON state packages over ad-hoc peer networks.

When the master modifies exposure values or hits record, settings are instantaneously pushed to all node nodes to execute uniform photometric capture rules.

Wi-Fi Aware & Ad-hoc NAN Networking

Standard local networks rely on a central wireless router to pass packets. In off-grid settings, we utilize the Wi-Fi Aware (NAN) protocol, enabling direct device-to-device wireless routing natively on the device chipsets.

In the office, the devices use a dedicated DeviceDiscoveryUI to handshake and store trusted cryptographic keypairs, allowing automatic connection in the field without cellular access.

Module 4

Microsecond Clock Sync & Frame-Dropping Protocol

Align multiple camera captures down to the exact microsecond despite variable latency over local wireless networks.

The Variable Latency Problem

D2D messages suffer from network transport jitter, taking between 10ms and 50ms to arrive. Triggering cameras with a direct "record now" command creates significant temporal offsets. At normal walking speeds, a 40ms offset shifts camera views by several centimeters, breaking rig extrinsics.

To resolve this, the system establishes clock parity using a network round-trip-time (RTT) calibration loop:

θ = ½ * [ (T1 - T0) + (T2 - T3) ]

Where θ calculates clock drift relative to local system uptime clocks.

AVFoundation Frame-Dropping Pipeline

When a recording session starts, the Master schedules a future timestamp (e.g. Master Time + 2.0s). The Satellite nodes receive this offset, spin up their AVCaptureMultiCamSession immediately, and route frames to background-threaded delegates.

These delegates discard every incoming CMSampleBuffer until the frame matches the target timestamp to the precise microsecond.

Module 5

High-Frequency Sensor Fusion & Spatial Priors

Accelerate point cloud reconstruction and register datasets in absolute coordinates using fused sensors.

Addressing Sensor Frequency Mismatches

During capture, telemetry sensors write data at different rates: video at 30/60Hz, GPS coordinates update slowly at 1Hz, and inertial sensors (IMU) sample motion at 100Hz+.

To associate GPS values and rotation rates with specific video frames, the system maps discrete hardware signals into a unified timeline using the high-resolution reference clock mach_absolute_time().

CoreLocation and CoreMotion APIs

CoreLocation provides coordinates (Latitude, Longitude, Altitude) to frame reconstruction bounding boxes.

CoreMotion uses the .xTrueNorthZVertical coordinate frame, fusing hardware sensor data to calculate 3-DoF rotation vectors (Quaternions) relative to true north and gravity. By interpolating orientation between 1Hz GPS steps, we produce high-fidelity 6-DoF spatial priors for every image.

Module 6

Real-Time Motion Blur Rejection

Implement a hardware-driven quality filter inside camera delegates to discard blurry frames prior to storage and processing.

Rotational Velocity & Shutter Exposure Physics

Motion blur smears high-frequency image details, corrupting feature point extraction. Rotational motions (Pitch, Roll, Yaw) cause significantly more feature smearing than linear accelerations.

Vulnerability to blur is linked directly to sensor exposure duration. In bright environments, short exposure windows (e.g. 1/2000s) freeze motion. In low-light environments, the shutter remains open longer, making the image highly susceptible to motion blur.

The Mathematical Gatekeeper Formula

The callback reads CMDeviceMotion rates directly. It applies a dynamic mathematical threshold test:

Threshold = Baseline Tolerance * [ 1 / (Exposure Duration * 60) ]

If the device's instantaneous rotational speed exceeds this threshold, the frame is excluded from serialization queues to save disk I/O and optimize points datasets.
