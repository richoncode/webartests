What this page does

Where it runsEntirely in your browser. Nothing is uploaded. Training, sampling, and storage stay on this device.
LibraryTensorFlow.js 4.22.0 from jsDelivr, same scripts as the MNIST demo. No npm install and no build step.
DataFashion-MNIST (Zalando): 28×28 grayscale clothing — T-shirt/top, trouser, pullover, dress, coat, sandal, shirt, sneaker, bag, ankle boot, in that official order. The page fetches the official 10,000-image test split as gzip IDX from jsDelivr, with GitHub raw as a fallback, then caches it in IndexedDB (browser-ai / fashion-mnist-10k-v1). Training uses 9,000 images and validation 1,000, a fixed shuffle of the whole pool. The 60,000-image training file is left on the server so the first visit stays small.
Dense CVAEThe WASM-trainable default. The class one-hot is projected to a 16-d embedding and concatenated into both hidden layers and the pixel logits. A zero-initialized template maps the one-hot straight onto those logits, so the class has a path that does not depend on z. Encoder: 784 pixels plus the embedding, two 128-unit ReLU layers, then 16-d mean and log-variance. Decoder: z plus the embedding, two 128-unit ReLU layers, then 784 sigmoid pixels. About 269k parameters. Loss is Bernoulli reconstruction (binary cross-entropy, summed over pixels) plus β times KL to the unit normal. β is 0.25 for a one-epoch run and otherwise moves from 0.05 to 1. Adam at 1e-3. Best-known preset: 8 epochs, batch 64. Captions are this conditioning input, not a classifier score.
Conv CVAEThe sharper VAE. Three stride-2 convolutions (32, 64, 128) take 28×28 down to 4×4. Latent size is 32, inside the 16–32 range that keeps garment structure without a huge code. The decoder maps z to 7×7 and uses three Conv2DTranspose stages (stride 1, then 2, then 2) back to 28×28×1 with a sigmoid. A learned class embedding is concatenated onto the image and the encoder bottleneck, and onto z and the 7×7 map — the conditional-VAE concat pattern, not a bias add. About 448k parameters. Adam 1e-3, Bernoulli BCE, same β warmup. Best-known preset: 50 epochs (50–100 is the range this usually needs), batch 64. This follows the convolutional VAE practice (conv encoder, transposed-conv decoder, BCE) used for Fashion-MNIST-sized images.
cDCGANThe sharpest option. Radford, Metz, and Chintala (DCGAN, 2015): Adam 2e-4, β1 0.5, latent noise 100. The generator is the 28×28 stack from the TensorFlow DCGAN tutorial — dense to 7×7×256, Conv2DTranspose, tanh in [−1, 1] — with batch norm in the generator. The discriminator is strided Conv2D, LeakyReLU 0.2, and dropout 0.3. Class conditioning follows Mirza and Osindero: a learned class embedding is concatenated into G (with z, and on the 7×7 map) and into D (as extra image channels, and again before the logit). About 3.1 million parameters. Training alternates one discriminator step and one generator step. Best-known preset: 50 epochs. This tab fills batch 64 so the browser stays within memory; the usual GPU recipe uses 128. Dashboard charts are G loss and D loss. Pixels are scaled to [−1, 1] for training and mapped back to grayscale for display.
SharpnessA VAE trains with pixel-wise cross-entropy, which averages the garments that share a code, so edges stay soft. A GAN’s discriminator penalizes that blur. On Fashion-MNIST, that is why a DCGAN-style model is the usual route to sharp samples and why published FID comparisons put adversarial models ahead of VAEs. The conv CVAE sits between the dense VAE and the GAN: the convolutions keep spatial structure, and the likelihood term still softens it.
BackendsAuto for the dense CVAE tries WebGPU (when navigator.gpu returns an adapter), then WASM, then WebGL, then CPU. Conv CVAE and cDCGAN need convolution training kernels. TensorFlow.js WASM does not ship Conv2D or Conv2DTranspose gradients, so Auto for those models tries WebGPU, then WebGL, then CPU, and skips WASM. Choosing WASM shows a status and moves the run to WebGL, WebGPU, or CPU when one of those exists. CPU can train the conv models, slowly. The banner names the backend that actually started.
SamplesThe class menu opens on Trouser. Generate draws a code from the unit normal and decodes it conditioned on the chosen class. cDCGAN uses that code as noise. The real-vs-generated strip places two cached Fashion-MNIST images of that class beside the samples, with matching captions. A finished training run fills that strip for every class (two real, two generated) and the class means. Class means decode the zero code once per class. Latent walk blends two codes in eight steps. The status line names the conditioned class.
PerfOne epoch of the selected model on 256 images, batch 32, that model’s learning rate, then 32 generated images timed after a 4-image warmup. WebGPU, WASM, WebGL, and CPU run only when this browser has them. WASM is skipped for Conv CVAE and cDCGAN. Results land in localStorage['browser-ai.fashion-perf'] for the dense model and in browser-ai.fashion-perf.conv-cvae or browser-ai.fashion-perf.cdcgan for the others. These runs do not replace the saved checkpoint.
StorageSeparate IndexedDB checkpoints, so the three models do not overwrite each other. Dense: indexeddb://browser-ai-fashion-cvae-e16-h128-z16-enc and …-dec. Older dense checkpoints (h64-z8) are not loaded. Conv CVAE: indexeddb://browser-ai-fashion-conv-cvae-z32-enc and …-dec. cDCGAN: indexeddb://browser-ai-fashion-cdcgan-z100-g and …-d. Run metadata is appended to localStorage['browser-ai.runs'] for the lab hub.
CaveatThese are 28×28 models, not catalog photos. The dense VAE looks soft after a short run. The conv VAE and the GAN need the longer preset, and the first conv batch spends time compiling kernels. WebGPU needs localhost or HTTPS. If a backend fails to start, Auto falls forward and the banner says which one took the job.
