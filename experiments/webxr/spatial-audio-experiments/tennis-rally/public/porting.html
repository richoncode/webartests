Porting Guide

This simulation's spatial audio — clip banks, force→volume mapping, distance falloff, reverb, and racket-position Doppler — was built directly against the Web Audio API. This guide maps each piece onto other real-time engines, starting with Unity + AR Foundation.

AudioSource / AudioMixer AR Foundation Resonance Audio (recommended)
Overall shape of the port: almost everything this tool's tuning panel exposes is plain data — a force→volume curve, a set of clip banks, distance/rolloff numbers, reverb levels — and ports directly as a C# class with the same field names. The only pieces that need an actual plugin instead of stock Unity are true HRTF spatialization and convolution-style reverb, since Unity's built-in audio doesn't ship either.

01 — Foundations

Spatializer & Reverb Plugin

Stock Unity's 3D audio is a simple distance-based panner — no head-related transfer function, and its reverb (AudioReverbFilter / AudioReverbZone) is a fixed set of algorithmic presets, not the convolution-against-a-recorded-impulse-response approach this tool uses (small-room.wav, outdoor-court.wav, stadium.wav). For real parity, install a spatial audio plugin before porting anything else.

Recommended: Resonance Audio. Android XR is one of the platforms this project targets, and Android XR ships a first-party Audio SDK built directly on "an updated Resonance Audio engine"[5] — HRTF spatialization, physical room-acoustics simulation from scene geometry, and precomputed reverb, all native to the OS with zero extra plugin install on that platform. Standardizing on Resonance Audio across every Unity target means the same spatializer choice carries through to Android XR for free, instead of running a different, redundant pipeline there.

Resonance Audio ✓ Recommended

On Android XR specifically: the platform's Android XR Audio SDK — built on this same updated Resonance Audio engine — is the natural, first-party choice, not a third-party add-on.[5] For the other Unity targets (iOS/desktop AR Foundation), the plain Resonance Audio Unity plugin keeps the exact same spatializer/reverb model consistent across every platform this project ships to, rather than mixing spatializers per-platform.
Steam Audio ✕ Not recommended here
Free, open-source, actively maintained, with generic Android CPU support (armv8/arm64, x86, x64).[1] HRTF spatialization plus true convolution-based reverb.[2] A genuinely strong plugin on its own — but it has no first-party integration with Android XR's own Resonance-Audio-based room-acoustics pipeline, so using it on that platform means running a second, redundant spatializer alongside (or instead of) the one the OS already provides for free, rather than reusing it.
FMOD (as audio backend) ✕ Not recommended here
Has a dedicated Convolution Reverb DSP that loads an impulse response file[6] and a visual mixer not unlike this tool's own tuning panel — but it means swapping Unity's entire audio backend, a much bigger lift than adding a spatializer plugin. The only production XR-specific FMOD spatializer is Meta's, built for Quest — there's no equivalent first-party FMOD integration for Android XR, so you'd be hand-rolling the room-acoustics simulation Android XR already gives you natively through Resonance Audio.

Once you've picked a spatializer, enable it under Edit → Project Settings → Audio → Spatializer Plugin, then on every 3D AudioSource: spatialBlend = 1 and spatialize = true.

02 — Clip Banks & Jitter

Racket / Floor Hit Categories

This app's AudioSettingsStore holds a per-category array of clip entries ({ url, enabled, volume }), a random-selection pool, and volume/pitch jitter fractions. Ports as-is — Unity has no built-in "weighted random one-shot with jitter", so this stays hand-rolled C# either way.

public class HitCategory
{
    public AudioClip[] clips;
    public bool[] enabled;
    public float[] clipVolume;
    public float randomVolumeJitter = 0.08f;
    public float randomPitchJitter = 0.06f;
    public int maxSimultaneousSounds = 6;

    private readonly List<AudioSource> _active = new();

    public void Play(Vector3 position, float volume01, float dopplerPitch)
    {
        // Evict the oldest voice once at the cap — mirrors maxSimultaneousSounds
        if (_active.Count >= maxSimultaneousSounds)
        {
            _active[0].Stop();
            _active.RemoveAt(0);
        }

        var enabledIndices = EnabledIndices();
        int pick = enabledIndices[Random.Range(0, enabledIndices.Count)];

        float jitteredVolume = volume01 * clipVolume[pick]
            * (1f + Random.Range(-randomVolumeJitter, randomVolumeJitter));
        float jitteredPitch = dopplerPitch
            * (1f + Random.Range(-randomPitchJitter, randomPitchJitter));

        var src = SpawnSourceAt(position);
        src.clip = clips[pick];
        src.volume = jitteredVolume;
        src.pitch = jitteredPitch;
        src.Play();
        _active.Add(src);
    }
}
Verified — this needs no conversion. AudioSource.volume is documented as a plain linear 0–1 scalar with a "linear taper"[12] — the exact same convention as this app's own GainNode.gain.value (see the Audio Physics page's note on why that's a simplification). So src.volume = jitteredVolume above is a direct, lossless 1:1 assignment — the web app's volume field and Unity's AudioSource.volume are the same kind of number. Don't confuse this with Section 06 below: the dB conversion described there applies only to AudioMixer's exposed group-level parameters, a separate mixing-bus layer — never to AudioSource.volume itself.

03 — Force → Volume Mapping

The Draggable Graph, As a Curve Asset

The two-point drag graph in this app's tuning panel (a piecewise-linear ramp: flat below forceMin, linear between the two points, flat above forceMax) maps almost exactly onto Unity's built-in AnimationCurve — its Inspector curve editor is a drag-to-edit graph, so designers get the same editing experience for free.

public AnimationCurve forceToVolume = AnimationCurve.Linear(0f, 0.05f, 14f, 1f);

float MapForceToVolume(float force) => forceToVolume.Evaluate(force);
Keep the same semantics as the web tool: "force" is a speed-equivalent (m/s), a weighted blend of racket/ball closing speed and each one's own speed — not a true physical force. Compute it identically on both sides so a tuning JSON exported from the web app maps onto the same curve shape in Unity.

04 — Distance & Rolloff

Min/Max Distance, Rolloff Factor, Venue Scale

Unity's AudioSource ships Logarithmic/Linear/Custom rolloff modes, but its "Logarithmic" curve isn't the same math as Web Audio's inverse distance model this app defaults to. For exact parity, sample this app's own computeAttenuation() function into a Custom Rolloff curve[7] instead of relying on Unity's presets.

05 — Doppler (the part that needs care)

Racket Velocity, Not Automatic Transform Doppler

This is the one piece most likely to get ported wrong. Unity's built-in AudioSource.dopplerLevel[8] computes pitch shift automatically from how far the source's Transform actually moved between frames relative to the AudioListener. That doesn't match this app's model: the racket-hit sound fires as a single instantaneous one-shot at contact, using an effective racket velocity derived from the ball's real outgoing direction (scaled to the animation's reported racket speed) — not the racket rig's own frame-to-frame transform movement, which isn't trustworthy for this.

Set dopplerLevel = 0 on these AudioSources and compute the shift manually — otherwise you'll get two competing, inconsistent Doppler effects layered on top of each other. 
const float SpeedOfSound = 343f;

float ClosingSpeedTowardListener(Vector3 sourceVelocity, Vector3 sourcePos, Vector3 listenerPos)
{
    Vector3 toListener = listenerPos - sourcePos;
    float dist = toListener.magnitude;
    if (dist < 1e-4f) return 0f;
    return Vector3.Dot(sourceVelocity, toListener) / dist;
}

float DopplerFactor(float closingSpeed)
{
    float clamped = Mathf.Clamp(closingSpeed, -SpeedOfSound * 0.9f, SpeedOfSound * 0.9f);
    return SpeedOfSound / (SpeedOfSound - clamped);
}

// At contact: derive effectiveRacketVelocity from the ball's outgoing shot direction
// (scaled to the animation's reported racket speed), exactly like BallAudio.js does —
// the racket rig's own raw velocity is not trustworthy as a Doppler source.
float pitch = DopplerFactor(ClosingSpeedTowardListener(effectiveRacketVelocity, racketPos, listenerPos));
audioSource.pitch = pitch * jitteredPitch;

06 — Mixing: Global / Racket / Floor Gain

Audio Mixer Groups

The tuning panel's globalGain, racketGainMultiplier, and floorGainMultiplier map naturally onto an Audio Mixer hierarchy: a Master group with Racket and Floor child groups, each independently controllable at runtime.

Mixer-exposed parameters are in decibels (Unity's mixer range runs from +20 dB down to a silent floor at −80 dB[9]), not the 0–1 linear gain this app's model uses everywhere. Convert with dB = 20 * log10(linearGain) before calling AudioMixer.SetFloat(...), or the sliders will feel completely different from their web-app counterparts. 
void SetGain(AudioMixer mixer, string exposedParam, float linearGain)
{
    float db = linearGain > 0.0001f ? 20f * Mathf.Log10(linearGain) : -80f;
    mixer.SetFloat(exposedParam, db);
}

07 — Venue Presets & Settings Portability

Reusing Exported Tuning JSON

The web app's Save Tuning JSON / Load Tuning JSON buttons already export this entire model as plain JSON with the exact field names used throughout this guide. Mirror AudioSettingsStore's shape as a serializable C# class and you can drop an exported tuning file straight into StreamingAssets as a first-pass starting point in Unity.

[Serializable]
public class SpatialSettings
{
    public string distanceModel; // "linear" | "inverse" | "exponential"
    public float minDistance, maxDistance, rolloffFactor, venueScale;
    public float coneInnerAngle, coneOuterAngle, coneOuterVolume;
    public float globalGain, racketGainMultiplier, floorGainMultiplier;
}

var settings = JsonUtility.FromJson<SpatialSettings>(jsonText);

08 — AR Foundation Specifics

Listener, Anchoring, and Mobile Performance

ConcernGuidance
Listener positionAttach the AudioListener to the AR session's Camera (under XROrigin / AR Session Origin[10]) — it then tracks the device pose automatically, the same way this app reads scene.activeCamera.position every frame.
World anchoringParent the court and its emitters under an anchor managed by ARAnchorManager[11] (or a plane detected via ARPlaneManager). Once anchored, ordinary local Transform positions on the racket/ball drive panning and distance exactly like Babylon.js scene-space positions do here.
Voice cap on mobileMobile AR is thermally and CPU constrained — keep maxSimultaneousSounds conservative (this app defaults to 6) and prefer triggering convolution reverb only on discrete hits rather than running it continuously.
Cross-platform spatializerNeither Apple's nor Google's native spatial audio APIs are exposed directly through Unity, which is why a cross-platform plugin matters for an AR Foundation app that has to run across iOS, Android, and Android XR from one project. Resonance Audio is the pick that stays consistent everywhere: it's the plain plugin on iOS/desktop, and on Android XR it is the platform's own first-party Audio SDK[5] rather than a third-party add-on running alongside it.
