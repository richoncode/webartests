Goal

The fire should make its own sound. A steady campfire crackles from heat, density, and motion in the simulation. An explosion is an impulse when a burst actually fires. The voice is Perry Cook’s PhISEM shape: a system energy that decays, Poisson events whose rate follows that energy, each event a noise burst times a short envelope, then a few bandpass resonances.

The first listening target is the campfire preset (editor/presets/campfire.json), played through the library the way examples/playback already plays an exported simulation. Explosions come after the steady fire is recognizable.

Experiment pathway

Do the phases in order. Each one has a stop line. Stop there and listen or measure before the next phase.

Phase 0 · Fork

Fork upstream onto richoncode/firesim

  1. Fork dgreenheck/threejs-fire-pro to richoncode/firesim.
  2. Branch audio (or firesimaudio) from that fork’s default branch.
  3. Install and run the editor (npm install, npm run dev). Open the campfire preset in a WebGPU browser and confirm it still simulates.

Done when the fork exists, the branch is checked out, and the hosted or local campfire still runs. Leave this webartests folder unchanged.

Phase 1 · Repo map

Find the fields, and what can reach the CPU

Start from the layout below (upstream main as of 6 Oct 2026). Confirm names on the branch. Private fields move.

  • src/library/FireSimulation.ts — public object. update(deltaSeconds), stats, debug({ field, bricks }), emitters, explosions, forces.
  • src/library/options.ts — DEBUG_FIELDS: beauty, lifetime, heat, smoke, velocity, flame, fuel, vorticity, expansion, pressure, divergence. Velocity and vorticity views show magnitudes.
  • src/engine/FluidSimulation.ts — GPU state. field packs heat, normalized flame lifetime, and fuel in YZW. X is smoke density in full mode, or that step’s smoke production when smoke cells are coarser. velocity is its own texture. Pressure and divergence are solver buffers. Vorticity confinement runs computeCurl when the vorticity setting is non-zero.
  • src/engine/shaders/ — WGSL for advection, forces, scalar transport, combustion, and the ray-marched volume.
  • editor/ — React editor, editor/presets/*.json (including campfire.json), preview scenes.
  • examples/playback/ — loads simulation.json and rebuilds emitters, forces, and colliders on a WebGPURenderer.

Debug field views replace the picture. They are a colormap, so sampling the canvas is a picture of the legend. The brick outline is a real readback: readBricks() maps a buffer, and the view refreshes only when 250 ms have passed and no read is in flight. Activity (active brick count, pool pressure) is copied every step and mapped asynchronously in readActivity. That pattern is the cheap readback. A full field texture mapped every frame is the expensive one.

CPU state that needs no readback: simulation.stats (simulationTime, droppedTime, activeVoxels, gridLimited, estimatedMemoryBytes), emitter options and world positions, force options, and explosion trigger().

Done when a short note on the firesim branch lists each candidate signal, whether it is already on the CPU, and whether a probe would be a new reduction or an existing readback.

Phase 2 · Probe layer

A few numbers per step, updated beside simulation.update

Prefer CPU proxies for the first probe object. Add a GPU reduction only for a signal the proxies cannot carry (usually heat or velocity magnitude inside the flame).

  • Heat or smoke density → energy and gain.
  • Speed or vorticity magnitude → crackle rate.
  • flame.cooling (and smoke dissipation) → how fast energy decays when the fire is quiet.
  • Explosion trigger() → an impulse on that audio block.
  • Emitter world positions → a flame centroid for later panning. lightAnchors() already gathers emitter positions for scene lights. A centroid can be the emission-weighted average of those positions.

If a GPU probe is required, copy the activity-read shape: one small buffer, copyBufferToBuffer, mapAsync(READ), at most one map in flight. A reduction (mean or max over a handful of probes, or over active bricks) is enough. Skip the full volume.

Done when a probe object updates once per simulated step and can be logged. No audio yet.

Phase 3 · PhISEM-lite AudioWorklet

The voice, driven by a slider before it is driven by fire

  1. A click (or key) resumes AudioContext. Browsers block audio until a gesture.
  2. systemEnergy decays every audio block. A control-rate input adds energy.
  3. Event rate follows energy (Poisson). Each event is noise times a short envelope.
  4. Two to four bandpass resonances color the events. Tune them by ear on noise first.
  5. Post the slider (later, the probes) from the main thread at control rate. The worklet does not read GPU memory.

Done when a slider makes a crackle that dies out when the slider returns to zero, and the context stays silent until the click.

Phase 4 · Wire playback

Campfire in, probes on a HUD, mute on a button

  1. Use examples/playback. Point it at an export of the campfire preset (the example’s checked-in simulation.json is the fire-tornado preset, which is a harsher first listen).
  2. After each simulation.update, copy the latest probes into the worklet.
  3. HUD: energy, crackle rate, cooling, last impulse, stats.activeVoxels, stats.droppedTime, stats.gridLimited.
  4. Mute toggle that gains the voice to zero and keeps the sim running.

Done when the campfire is audible, mute is instant, and the HUD numbers move with the fire.

Phase 5 · Perf budget

Audio stays off the WebGPU frame

The solver already slows down when a frame misses 1/60 s: update runs at most one step and adds the rest to stats.droppedTime. Extra GPU readback makes that worse. The viewport can show per-pass GPU timings (src/engine/GpuProfiler.ts).

  1. Record frame time and droppedTime with the voice muted and probes off.
  2. Turn probes on, then the worklet. Compare.
  3. If frame time moves, lower the probe rate (the brick view’s 250 ms cadence is a known-safe pace).
  4. If it still moves, drop the GPU reduction and keep CPU proxies plus explosion impulses.

Done when a short note on the branch records the before/after timings and which probe rate shipped.

Phase 6 · Polish

Place the sound, then consider bandwidth

  • Pan with the flame centroid from phase 2 (PannerNode or a stereo balance). The centroid moves when emitters move. The FireSimulation object itself stays at the identity.
  • Stretch goal, only after the campfire already sounds like fire: bandwidth extension in the sense of Chadwick and James, low-frequency content from the sim plus synthesized highs. See reading below.

Done when moving the campfire in the scene moves the sound. Bandwidth extension is optional and can stay unstarted.

Phase 7 · Share

Write down the mapping, then offer it upstream

  1. On the firesim branch, document which signals were sampled, the probe rate, and the phase 5 timings.
  2. Record a short campfire clip with mute shown.
  3. Send that to the upstream author. Open a PR to dgreenheck/threejs-fire-pro only if the branch is reviewable (MIT, no unrelated editor churn).

Done when the note and the clip exist, and the offer has been sent.

Fire Pro review

Fire Pro is a library plus an editor. The library drops into a Three.js WebGPURenderer scene. The editor designs an effect and exports JSON, JavaScript, or a standalone page. MIT license. Bundled fonts, models, and textures are listed in THIRD_PARTY_NOTICES.md and stay under their own terms.

  • src/library — FireSimulation, handles, options, volume rendering, scene lights.
  • src/engine — sparse GPU fluid solver: staggered velocity, pressure projection, buoyancy, vorticity confinement, MacCormack scalar transport, optional fuel combustion.
  • src/engine/shaders — WGSL compute and the ray-marched volume.
  • editor — React editor, built-in presets, preview scenes, debug views, GPU timings.
  • examples/playback — play an exported document with the library. Space retriggers burst emitters.

The solver is sparse. Voxels exist near emitters and near visible flame, smoke, and fuel. Quality is voxelSize and grid.maxVoxels. Halving the voxel size can mean up to eight times the cells for the same volume.

What that implies for audio

Heat is art-directed. It drives buoyancy and ignition. It is a relative quantity. Flame color uses a blackbody curve, and the rendering temperature is a look control. Map heat and density onto energy by ear. Skip a Kelvin conversion.
  • WebGPU only. There is no WebGL fallback. The playback page already requires a WebGPU browser. The synth does not change that.
  • Fixed 1/60 s step (FIXED_DT in src/engine/types.ts). update runs at most one step per call. Slow frames drop time into stats.droppedTime and the fire slows down. The AudioWorklet keeps its own clock. When droppedTime climbs, hold the last probes and let systemEnergy decay. Inventing extra sim frames would put crackle ahead of the picture.
  • Voxel budget. Cells past grid.maxVoxels stay empty (stats.gridLimited). Wide smoke can vanish. Probe levels can step down when that happens. Treat it as a level change.
  • Readback is already asynchronous and small. Follow readActivity / readBricks. A new probe that maps the whole field texture will fight the frame budget in phase 5.
  • Lights and the framebuffer are the wrong source. Scene lights do not change the simulation. Debug views are colormaps. Sample solver state or emitter state.
  • Integration point. examples/playback already calls simulation.update then renders. Put probes next to that call. The editor is the wrong first host.
  • Identity transform. FireSimulation stays at the identity and runs in world space, ground at y = 0. Spatial audio follows emitter positions.

Reading

Perry Cook, PhISEM (physically informed stochastic event modeling). A particle system has an energy. Collisions are a Poisson process whose rate depends on that energy. Each collision is noise times an envelope, heard through resonances. That is the voice in phase 3. Cook used it for particle instruments such as shakers. PhISEM is the method to implement. Fire CFD is a different literature.

Jeffrey N. Chadwick and Doug L. James, Animating Fire with Sound (SIGGRAPH 2011). Combustion sound from a fire simulation: low frequencies taken from the flow, with bandwidth extension for the highs. That is CFD-driven fire audio, and it is the optional stretch in phase 6. It is a different method from PhISEM.

James F. O’Brien, Perry R. Cook, and Georg Essl synthesized sound from physically based motion, including modal sound for deforming tetrahedral solids (the ringing bowl). That work is about solids. It is context for Cook’s name next to physical audio, and it is off the path for this fire synth.
