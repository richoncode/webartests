The Latent Intelligence Shift

"Keeping representation in the latent space allows the model to reason about physics without the overhead of per-pixel reconstruction."

P

Pixel-Space Paradigm

  • ❌ High GPU memory overhead per frame
  • ❌ Sensitive to lighting/texture noise
  • ❌ Loss functions: PSNR, SSIM, LPIPS
  • ❌ Slow convergence on motion tasks
AMI

Latent-Space Paradigm (AMI)

  • ✅ Action-centric feature extraction
  • ✅ Structured latent bottlenecks (Spatio-temporal)
  • ✅ Loss functions: KL-Divergence, Action MSE
  • ✅ Real-time reasoning (Short-circuiting render)

AMI Data Flow: Short-Circuiting the Splat

In AMI's architecture, 3D Gaussians or Meshes are often treated as Auxiliary Decoders. The core policy network does not need to render the splats to know what action to take.

INPUT

RGB-D + Prompts

Point clouds & Prompt Workloads

CORE BOTTLENECK

Latent State (Z)

Physics-Aware Embeddings

OUTPUT

Action Trajectory

Motor Torque / Joint Deltas

OPTIONAL DECODER

3D Splat/Mesh

Only used for Visualization or Training Supervision

Efficiency Comparison

By operating in the Latent Space, models achieve significantly higher inference frequencies (Hz). Pixel-space models are limited by the rasterization speed of the splats, which creates a throughput bottleneck in high-speed manipulation.

Underlying Papers & Data Types

Action-Centric Latents

Found in papers like "Learning Latent Dynamics for Planning". Focuses on ΔZ transitions rather than pixel deltas.

Prompt Workloads

Generative scripts that define Initial Latent States for simulators like PartNet-Mobility.

Gaussian Primitives

Used as a Structured Bias in the encoder to help the model learn geometry faster.

Hierarchical VLAs

Vision-Language-Action models that map language to Latent Goals, not pixel targets.
