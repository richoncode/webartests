How to read this

  • Particles are bytes moving memory → cache → compute. Dot speed and dots per second scale with effective bandwidth (published GB/s × bandwidth efficiency) on one scale for both panels. dot rate ∝ memory bandwidth.
  • Bright compute cells are doing math. Dim amber cells + STALL are waiting on memory. On M5-generation Apple GPUs the bright inner square is the Neural Accelerator, the matrix unit in each GPU core.
  • Layer strip: each column is one transformer layer, attention on top and feed-forward (MLP) on the bottom. Amber means that half is waiting on memory; green means it is limited by compute. With Run on Neural Engine, pink N is the Neural Engine and blue G is a GPU fallback.
  • verified published figure approximate / derived / third-party assumed
  • Range bar blue: efficiency ×0.8 to ×1.2 white: central estimate amber: peak at 100%
  • One package: all-reduce time in the step is 0 s, so tok/s comes only from this chip's compute and memory bandwidth. The model is not split, so weights and the KV cache have to fit here.
  • FP8 on Apple GPUs stores weights in 8 bits and runs the matmul in 16-bit, because those GPUs have no native 8-bit math.
  • Apple memory blocks are drawn in proportion to bandwidth. The count is not a count of memory packages.
